# Release pipeline and repository hygiene

The owner's ruling (2026-11-07): yes to CI building the app on a tag, and to the other practices of a professional open-source desktop app. Today a release is built and signed only on the owner's Mac (`pnpm release`, PLAT-25), so nobody can check that a published `.dmg` came from the code on GitHub, and the newest published release is v0.1.0.

1. **Release on tag (PLAT-37).** Pushing a `vX.Y.Z` tag runs a workflow on a GitHub-hosted macOS runner: `pnpm release` builds, signs, notarises and staples the app, then uploads the `.dmg`, the updater archive, its `.sig` and `latest.json` to a GitHub release. The Developer ID certificate, its password, the notary credentials and the updater key are repository secrets, set by piping, never printed. The release script stays the one home of the steps; the workflow only calls it. A dry run on a pre-release tag comes first.
2. **Build provenance (PLAT-38).** The workflow attests every release file (`actions/attest-build-provenance`), so anyone can run `gh attestation verify <file> --repo jahala/conducted`.
3. **Release notes and changelog (PLAT-39).** The release writes its notes from the commit subjects since the last tag, grouped by area, and adds them to `CHANGELOG.md` in the same release commit. `CHANGELOG.md` is the one home of the notes: the GitHub release body is cut from it, the product page (#356) builds its Changelog page from it, and the app's update notice links to that version's entry on the page.
4. **Branch protection (PLAT-40).** `main` takes changes only through pull requests, and the `typescript` and `rust` checks must pass before a merge. The `harness` job is left out because it runs only when a pull request touches the screens, and a required check that never runs would hold a pull request forever. A script checks the rule is set and fails when it is not.
5. **Code scanning (PLAT-41).** CodeQL for TypeScript and Rust on pull requests and weekly on `main`. Secret scanning and push protection were turned on 2026-11-07.
6. **Homebrew cask (PLAT-42).** `brew install --cask conducted` from a tap (`jahala/homebrew-tap`), updated by the release workflow from the published `.dmg` and its checksum.
