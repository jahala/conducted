# Coverage audit: app shell, navigation and global UI

Audited against `docs/research/conductor/ui-map.md` sections 1, 2, 4 and 5, and the related rows of `structure-map.md`. Scaffold folders checked: `app/`, `features/{sidebar,home,dashboard,palette,passport,workspace,onboarding}/`, `core/registries/commands.ts`, `core/services/command-runner.ts`, `ui/`, plus the places those files point to (settings, updates, diagnostics, git-panel, composer, file-viewer, Rust `menu.rs`).

File paths in the tables are relative to `apps/desktop/src/` unless they start with another folder. "Registry" means `core/registries/commands.ts`. A registry id such as `app.commandPalette` is a command entry there. Rows for numbered key families (`Cmd+1` to `Cmd+9`) are merged into one row.

Status words:

- **Covered**: an owning file exists and its header or registry entry names the item.
- **Partly**: an owner exists, but its spec leaves out a detail. The Fix column says which.
- **Missing**: nothing owns it.
- **Out of scope**: team, hosted-account, internal-build or non-macOS item (D004, D018).
- **Planned (cloud)**: belongs to the cloud option or Remote Control (`docs/plans/cloud-and-remote.md`). A backlog id is given where one fits. Where none fits, a new id is proposed.

## Summary

485 items audited.

| Status          | Count |
| --------------- | ----- |
| Covered         | 327   |
| Partly          | 37    |
| Missing         | 37    |
| Out of scope    | 69    |
| Planned (cloud) | 15    |

Most shortcut rows are Covered because the registry holds real data for them. The Partly and Missing rows are mostly small spec gaps in file headers. Eleven new backlog ids are proposed at the end.

The five findings that matter most:

1. **No key dispatcher.** The registry holds 140 commands with parsed shortcuts, `CommandRunner.run(id)` runs one by id, and Rust emits `menu://command`. Nothing in the UI listens for key presses or for the menu event, resolves the scope (chat input, terminal, diff, dialog), applies the user's overrides and the send-key swap, or pushes accelerators to `menu_set_shortcuts`. Without it, no shortcut in section 5.4 does anything. Proposed as NAV-14.
2. **No visible Settings entry.** In Conductor the account menu holds "Settings". We removed that menu. The sidebar footer now has no Settings button, so the page is reachable only by `Cmd+,`, the app menu and the palette.
3. **The long-lived "surface" layer has no owner.** Terminals and browser previews must survive tab switches. `workspace/TabContent.tsx` says they remount for now. Proposed as NAV-15.
4. **Backlog workspaces have no owner.** The registry has `workspace.addToBacklog` and `workspace.startFromBacklog` (both WS-01), but no file describes an unstarted workspace, "Add to backlog" or "Start". Proposed as WS-11.
5. **Registry gaps against the research table.** Missing commands: loadout select (`Cmd+Ctrl+1` to `5`), insert snippet (`Cmd+;`), save goal (`Cmd+Enter` in the goal bar), open sidecar logs, port forwarding toggle (`Cmd+Y`), open cloud workspace remotely (`Cmd+Alt+O`). The nine video keys have no spec.

Smaller inconsistencies worth a decision:

- `app.sendFeedback` (`Cmd+Alt+F`, APP-03) exists in the registry, but `src-tauri/src/menu.rs` leaves "Send Feedback" out because it points at a hosted service. No file says what the command does.
- `features/palette/KeybindingEditor.tsx` (NAV-09) and `features/settings/keyboard/ShortcutRecorder.tsx` (SET-02) both record a key combination. `ShortcutsDialog.tsx` and `settings/pages/KeyboardShortcutsPage.tsx` both list and rebind commands. One home per rule: pick one recorder and one list component and let the other surface embed it.
- Research gives `Cmd+Shift+L` to both "Open sidecar logs" and "Pull latest from main". The registry keeps the git meaning only. A sidecar-logs command should ship unbound.
- `app/AppShell.tsx` does not read or write `savePanelLayout` yet, so the sidebar width in `left_panel_width` is never saved. The spec covers it (NAV-01).
