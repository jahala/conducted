# Coverage audit: the workspace screen

Area: `docs/research/conductor/ui-map.md` section 3 (3.1 to 3.12), `frontend.md` section 5, and `sessions-and-chats.md` "Questions, approvals and plans". Checked against the scaffold in `apps/desktop/src` (folders workspace, chat, composer, git-panel, diff, file-viewer, pr, terminal, scripts-panel, browser-preview, open-in, core/status, core/api.ts, core/model.ts), plus the neighbours that own related pieces (app, sidebar, palette, settings, core/services, core/registries, packages/protocol, packages/sidecar).

Reading guide:

- `D/` means `apps/desktop/src/`. An id in brackets is a backlog id from `docs/plans/backlog.md`.
- Status classes: Covered (a file owns it and its header names it), Partly (an owner exists but its header or the API leaves out a detail), Missing (nothing owns it), Out of scope (team-only or internal to Conductor), Planned (cloud) (cloud workspace item for the plan in `docs/plans/cloud-and-remote.md`).
- "Covered" rows have no fix. "New" ids are listed at the end and are proposals only.
- I read every file header in the listed folders. I did not run anything.

Main findings, in order of weight:

1. The new workspace flow (3.9) has one placeholder page. The "New workspace" dialog, "Add to backlog", "Start", the unstarted state, the clone dialog and the quick-start dialog have no file. The page also needs repo-level file search and PR/issue list hooks that the API does not have.
2. Dialogs in 3.10 have no files: Link issue, Link workspaces and directories, Link pull request.
3. Several composer pieces are named in the research but owned by nobody: saved snippets, the Codex goal bar, the per-command behaviour of the built-in slash commands, the MCP status button, and the "Editing queued message" banner.
4. Tool cards: the canonical tool list in `packages/protocol/src/tools.ts` has no task, image, monitor, tool-search or Node REPL tool, so those calls fall to the generic card.
5. API gaps: mark chat or workspace unread, retry or discard a failed send, request a review, hide a PR comment, cache token counts on a turn, and sender of a user message.
6. Cloud items are all unowned in the scaffold, as planned. Four new CLOUD ids are proposed.
