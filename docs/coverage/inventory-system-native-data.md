## Findings that matter most

1. **Nothing for macOS release packaging exists.** No entitlements file, no `Info.plist`, no signing identity, no notarisation step. Conductor ships hardened-runtime with three entitlements (JIT, unsigned executable memory, microphone) and four usage strings (microphone and the Desktop, Documents and Downloads folders). The sidecar is its own signed program and needs the JIT entitlements on its own signature. Dictation and the sidecar are likely to fail in a signed build without this; test it with the first signed build. One NEW-PLAT row covers it.
2. **The agent download manager (D021) has no backlog row.** Conductor's binary manager is one module with a progress event, SHA-256 checks, retry, prefetch of the next versions, old-version cleanup and quarantine stripping. `sessions-agents-native.md` still treats it as "write the spec" (PLAT-28), which was right under D009 and is wrong since D021 replaced D009. The same stale reasoning marks a bundled `gh` as out of scope. D021 names agent programs only, so the `gh` question needs a decision.
3. **Review comments lose their life cycle.** Conductor keeps a state per comment (draft, pending, ready for review, reviewed, hidden, superseded), links attachments to the comments they carried (`comment_id`), and stores comments on the pull request itself (no file) and the author's avatar. Our `diff_comments` has none of these, and `file_path` is NOT NULL. Visible effects: "added to chat" status, dismissing a GitHub comment (ours would delete it and sync it back), PR-level comments in the PR tab. This needs migration 0004 and is a D020 gap.
4. **The Platform interface has no door for four things the Rust side already offers or needs:** dropped files with their real paths (`tauri://drag-drop`), `attachment_materialize` and `image_resize`, `menu_set_shortcuts`, and window focus and network events. Without the first two, dropping a file into the composer cannot work.
5. **Window look and permissions.** `capabilities/default.json` lacks `core:webview:allow-set-webview-zoom` (not in the `core:webview` default set, checked in `gen/schemas/acl-manifests.json`), so the App zoom setting cannot act. Vibrancy, traffic-light position and the Full Disk Access row have no command. `opener:default` cannot open the Privacy pane or IDE schemes.
6. **The repo's remote name has two homes.** `RepoConfig.remoteName` (`model.ts`) is what Settings, Git, "Remote origin" would write. `core/lookups.ts` ignores it and derives the remote from `target_branch`. A chosen remote would never be used.
7. **Menu and quit.** Cmd+Q does nothing if the UI has not mounted (Conductor has a "quit handler ready" hand-shake). `menu.rs` leaves out Send Feedback while APP-09 proposes it. "Toggle Web Inspector" cannot work in a release build because Cargo enables no `devtools` feature.
8. **Smaller data gaps:** the active chat per workspace is not stored (`active_session_id`); unarchive cannot change the folder or path; opening a workspace clears the unread dot of chats that still wait for the user; `setConfig` has no guard against a late write; attachments lack a loading flag and the `pdf` kind.
9. **Keep-awake needs no Rust.** Conductor runs `caffeinate -i` from the UI through its shell plugin. Our `shell_start` is enough, so the `R/power.rs` that `sessions-agents-native.md` proposes can be dropped.
10. **First-pass ids collide.** `PLAT-21` to `PLAT-23` mean different things in `sessions-agents-native.md`, `services-and-data.md`, `settings-states-kit.md` and `inventory-controls.md`; `APP-08` and `APP-09`, `SET-08` and `CLOUD-10` collide the same way. Nothing is in `backlog.md` yet. This report uses titles, not numbers, for new rows. The ids need one reconciliation before they enter the backlog.
11. **11 rows rest on a file header or a first-pass call with no decision entry.** D020 asks that each visible difference be listed in a decision. They are marked "Header only" or "No decision entry" in the tables.

## Method

- **Rust.** The two TSV files (`rust_identifier.tsv`, 139 rows; `rust_event.tsv`, 68 rows) are mostly library text (tokio, tao, h2, hyper, sqlx, nucleo, Tauri permission names, HTML boilerplate). They do not list Conductor's command names. The command and event list therefore comes from `native-and-sidecar-map.md` A2, A4, A5 and `frontend.md` 3a and 3b, and each name was checked against the TSVs and against `strings` on the binary. The TSV hits that name Conductor features (`app_actions`, `app_logger`, `db_rollback`, `resource_usage`, `port_forward`, `sync_loop`, `native_http`, `quit_requested`, `stop_sidecar`, the `update_*_updated_at` triggers, `set_webview_zoom`, `start_dragging`, the posthog and updater hosts, the drag and focus events) are all in the tables. Library text is not.
- **Permissions.** `macos_permission.tsv` has two rows (the Privacy pane scope and the quarantine attribute). Entitlements and usage strings come from `codesign -d --entitlements -` and `plutil -p` on the installed app, both read-only.
- **SQL.** All 319 statements in `sql-statements.txt` were read and grouped by table and operation. Most hit `workspaces` (87), `session_messages` (52), `sessions` (34), `diff_comments` (25), `attachments` (18), `identity_associations` (17) and `port_forwards` (16).
- **Scaffold.** Every `src-tauri/src/*.rs` header and the `generate_handler!` list, `capabilities/default.json`, `tauri.conf.json`, `Cargo.toml`, `platform.ts` and `tauri.ts`, the migrations, and every repository file in `core/db`.
- **Rule for first-pass proposals.** An id proposed in an earlier coverage file but absent from `backlog.md` is not "Covered". The row is Gap or Research only, and the id cell names the proposal.
- **Path shorthand.** `R/` is `apps/desktop/src-tauri/src/`, `D/` is `apps/desktop/src/`, `S/` is `packages/sidecar/src/`.
