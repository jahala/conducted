# Coverage check against Conductor: messages, sidecar tags, RPC methods and tools

Scope: `toast.tsv`, `sidecar_log_tag.tsv`, `sidecar_rpc_method.tsv` and `sidecar_tool_name.tsv` in `.context/conductor-re/inventory/`. Checked against `CLAUDE.md`, `docs/plans/backlog.md`, `docs/decisions.md`, `docs/research/conductor/`, `packages/protocol/src/rpc.ts`, the sidecar modules and the file headers in `apps/`, `packages/` and `bin/`. The Conductor material was read for behaviour only (D002). Everything below is in our own words; the quoted strings are UI messages.

How to read it:

- "Row N" is the Nth data row of the TSV (first row after the header). Offsets are in the bundle named in the TSV.
- `toast.tsv` holds 1051 strings. Most are developer log lines or library errors. A string counts as user-facing only when it is passed to the toast function of its bundle (`kt`, `Xi`, `ec` in renderApp; `Ht`, `Ct`, `feedback.toast` in main). That gives 266 strings; 13 of them (the window and remote-command log helpers) are logs, so 253 are judged. Everything else is "Noise".
- A few log lines outside that set are used as evidence of a failure case. They are in their own table and are not in the counts.
- Classes: Covered, Research only (the research mentions it, no scaffold file owns it), Gap (neither), Out of scope, Planned (cloud or Remote Control rows), Deliberately different (D005 to D019 or a design choice in a file header).
- A string is "Covered" when a file header, a "Must handle" line, a protocol method or the generic error-toast path owns the behaviour. Pure copy-to-clipboard and "Failed to X" toasts for actions we have are Covered by the owner of the action.

Out of scope are `RunLocalCommand` (a cloud agent running a command on the user's Mac) and the five "computer" tools (`ListComputers`, `GetComputerConfiguration`, `CreateComputerConfiguration`, `GetComputerBuildStatus`, `UpdateRepositorySetupScript`), which belong to Conductor's hosted computers.
- RPC Planned: the five `codexCloudAuth*` and `cursorCloudAuth*` calls move a subscription login into a cloud sandbox (open question in `cloud-and-remote.md`, Part 1 item 6), and `remoteControlStart`, `Stop`, `Status` map to RC-01 and RC-02 (a different mechanism, claude.ai instead of Conductor's phone relay). The phone pairing calls and `frontendRelay` are Out of scope.
- RPC Deliberately different: `setModelCatalog` (the sidecar owns the model list, SIDE-14 header) and `listLocalhostPorts` (we read listening ports through `lsof` in the shell, `core/services/ports.ts` header).
- Toast Out of scope (92) is mostly accounts and teams (sign-in, profile photo, organization info, templates, artifacts, routines, webhooks), Conductor's hosted GitHub App and loadout sharing, staff settings, and one Linux-only message ("No terminal emulator found").
- Toast Planned (14) are cloud workspace messages: port forwarding checks, "Restarted workspace", remote editor open, preview through a local mirror, cloud agent credentials, file download.
- Toast Deliberately different (4): "API key saved", "API key removed", "API key imported from env" and "Enter all required Bedrock fields." The Agents page header leaves out per-provider key entry and Bedrock fields; the agent programs and their logins stay on the user's machine (D009).

## Limits of this check

- User-facing strings were picked by the name of the minified toast function in front of each string. A message shown through another helper would sit in "Noise". The 266 strings were read in full; the 785 others were skimmed by text only.
- "Covered" for a message means a header, a "Must handle" line, a protocol method or the generic toast path owns the behaviour. I did not run any code, and I did not check that the owner's code body exists, only its header.
- The "Out of scope" calls for MCP connect messages (rows 690 to 694) rest on the code next to them: it carries an organization id and update and disconnect calls for organization servers. If they turn out to cover local servers, they move to SET-05.
