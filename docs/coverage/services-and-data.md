# Coverage audit: services, data, git and platform subsystems

Scope: `docs/research/conductor/services-map.md` (parts 1, 2, 3, 5A, 5B, 6 and both appendices) and `docs/research/conductor/frontend.md` sections 3, 4, 6 and 7. Part 4 of the services map (feature flags and settings keys) belongs to the settings audit and is not covered here, except where a subsystem reads a setting.

Checked against: `apps/desktop/src/core/**`, `apps/desktop/src/platform/**`, `apps/desktop/src/app/startup.ts`, `docs/data-model.md`, the three migrations, `bin/*.sh`, and `docs/plans/backlog.md` as it stands. The audit is read-only. It changes no code and no other doc.

How to read the tables:

- Covered: a service method, repository SQL, command builder or spec text in a file header handles it.
- Partly: something handles it, but the item named in the Fix column is missing.
- Missing: nothing handles it.
- Out of scope: team-only, Conductor's own backend, analytics or internal-staff tools (decisions D004, D009).
- Planned: cloud or remote host work. The CLOUD id is the closest backlog row. Where none fits, the Fix column proposes one.
- Paths are relative to `apps/desktop/src/` unless they start with `bin/`, `docs/` or `packages/`. `sm` is `services-map.md`, `fe` is `frontend.md`.
- A Covered row means the spec and the signature exist. Most bodies are still placeholders, so "Covered" does not mean "works".

The scaffold covers the local core well. The data layer, the git and gh command catalogue, the lifecycle rules and the file headers match the research closely, and the SQL is tested on a real database. The gaps sit in three places: the glue that connects finished pieces, a few read paths that screens already ask for, and a handful of small contract fields.

Biggest gaps, most important first:

1. Startup wiring is incomplete. `container.ts` builds every service but no step connects the dock badge, notification clicks, deep links, update checks, the quit handler, the Spotlight crash heal, or the agent list refresh after the sidecar starts. `app/startup.ts` and `container.start` both describe the sequence. The `archiving` rows that repair reports are not acted on. Fix in APP-01.
2. Two settings never reach the agent. `container.ts` passes `undefined` as the user preference text, so `custom_prompt_general` is dropped. The user's environment variables (`SettingsService.environmentFor`) have no field in `sendMessage` or `WorkspaceContext`. Fix in CHAT-02, SIDE-09, SET-04.
3. `archived_at` and `compacted_at` (migration 0002) are used nowhere. The compaction SQL counts from `workspaces.updated_at`, so a note or a pin on an archived workspace restarts the 90 day clock, and DATA-06 has no column to count 30 days from. Fix in DATA-02, DATA-06, WS-05.
4. GitHub read paths the screens ask for have no service method. `useBranches`, `useCheckLog`, `usePullRequestActivity` and `useStack` are named in `hooks.ts`, but `GitService` and `GithubService` have no matching methods. The PR fragment omits reviewers, deployments, required checks and the author, and no query builder fetches them. No code lists GitHub issues or PRs for the new-workspace picker. Fix in PR-03, PR-04, PR-07, PR-08, GIT-12 (new), PR-11 (new).
5. No shared async helpers. Headers in ingest, composer, sections, GitHub and Git require a serial queue per key, a single-flight dedupe and a latest-wins guard. Only `KeyedMutex` exists, inside `core/git`. Fix in APP-08 (new).
6. Keep-awake has a setting and no service. Fix in APP-09 (new).
7. Run actions are too thin. `RepoConfig.runScripts` holds `id`, `label`, `command`. The research also has args, cwd with variables, default, icon and hide. Fix in RUN-01, SET-07, DATA-05.
8. Review comments can not be dismissed or re-anchored. A GitHub comment the user deletes comes back at the next sync, no SQL moves a comment's line numbers, and `syncRemote` has no scope for a failed fetch. Fix in REV-03, REV-04.
9. A repo-level terminal has no home. `terminals.workspace_id` is NOT NULL, but Spotlight and the research use one terminal per repository. Fix in RUN-06.
10. Window focus is not an event. Polling "only while focused" and the update recheck need `Platform.app.onFocusChanged` (PLAT-22, new).

Three schema decisions are open and can share one new migration (0004): a `pdf` attachment kind, a dismissed flag on diff comments, and a `repo_id` on terminals. A migration may also drop the unused `session_events.compacted_at`.

Out of scope in this area: Conductor's accounts, organisations, Roundhouse backend, routines, analytics and Sentry, text-to-speech, the agent download manager (D009), and the legacy `conductor.json` migration. Part 4 of the services map (flags and settings keys) is audited separately.
