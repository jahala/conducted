# Coverage audit: Conductor UI controls against the scaffold

Pass two of the coverage check. It reads Conductor's own UI strings (labels, descriptions, aria labels, placeholders, test ids, routes) and asks whether our research and our scaffold know about each one. Source: `.context/conductor-re/inventory/{label,description,aria_label,placeholder,test_id,route}.tsv`. Context came from the two UI bundles, for understanding only (D002). Everything below is in our own words; only UI labels are quoted.

## How to read this

- **Covered**: a scaffold file, registry entry or header owns the feature, or the backlog has a row for it. A placeholder body still counts, because the scaffold is a spec.
- **Research only**: `docs/research/conductor/` describes it, the scaffold does not own it.
- **Gap**: neither has it.
- **Out of scope**: team or hosted features and Conductor's internal tools, per `docs/plans/scaffold.md` (organizations, sign-in, sharing, routines, pokes, profiles, team artifacts, billing, phone remote control, file sync, cloud desktop, Roundhouse, staff-only pages, Windows window buttons).
- **Planned**: cloud workspace items that match the CLOUD rows in `docs/plans/backlog.md`.
- **Skipped (noise)**: bundled-library text (mermaid shape names), code identifiers and log tags, test models, generic messages with no feature behind them.

Strings were matched by the feature they belong to, not by exact text, because the scaffold words its labels itself. Where a feature is split (research has it, the scaffold names it only as "left out"), it is **Research only**. IDs with a source in brackets were already proposed by the first pass in `docs/coverage/*.md`.

## Notes on judgement calls

- Model names (`label.tsv` 4-40) are Covered: SIDE-14 lets each runner report its own list on purpose. Piccolo is Out of scope (named in `docs/plans/scaffold.md`).
- Notification sound names and the rarity tiers are Covered: the registry offers two sounds by design and `passport-places.ts` plans our own place list. Decision 8 in `scaffold.md` forbids copying the sound files and city lists.
- GitHub App permission lists and the "token rejected" toasts are Out of scope. We use `gh`, so there is no app install or token.
- The profile activity page (heatmap, streak, chats per day, model share) is Out of scope as a team profile (`ui-map.md` section 2).
- Port forwarding rows (strategies, port range, "Forward port", "Waiting for ports") are Planned under CLOUD-09. The custom minimize and maximize buttons (a non-macOS title bar) are Out of scope.
- Strings under "Roundhouse", "Sandbox SHA", "Charged" and similar are Conductor's staff diagnostics for its hosted cloud. They are Out of scope.
- The nine Gap rows cover 35 strings (13 in `label`, 18 in `description`, 3 in `aria_label`, 1 in `test_id`). Neither the research notes nor the scaffold mention them. The Research only rows mostly repeat what the first pass found, so their ids are reused.
- Covered is judged from file headers and the backlog, not from running code. A Covered string can still sit behind a placeholder body.
