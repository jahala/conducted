# Coverage audit: Conductor's own UI text (text, title and tooltip strings)

Second-pass check of the scaffold against Conductor 0.92.1 itself. It reads the user-facing strings in `.context/conductor-re/inventory/` (`text.tsv`, `title.tsv`, `tooltip.tsv`), finds which component each belongs to by its offset, and compares that behaviour with `docs/research/conductor/` and with `apps/`, `packages/`, `bin/` and `docs/plans/backlog.md`. The bundle is used to understand behaviour only (D002). Date: 2026-11-04. Read-only: nothing but this file was written.

## How to read this

- File codes in the "Where" column: R = `renderApp-DeUrsznk.js`, M = `main-BE1h_1MP.js`. The number is the character offset, as in the inventory.
- Strings from one component sit at nearby offsets, so each string was judged with its neighbours. A string counts as **Covered** when the scaffold has a file or backlog row for the behaviour, even if our wording differs. Generic loading, empty and error messages count as Covered by APP-04 when their screen exists.
- **Research only**: the research describes it, the scaffold has no file, row or registry entry for it. **Gap**: neither has it. **Planned**: a CLOUD or RC row in the backlog covers it. **Out of scope**: team, account or Conductor-hosted. **Noise**: key-cap glyphs, schema fragments, sample code.

## Method and limits

- Every string in the three files was classified once (counts above). Strings were grouped by component using offsets, and every group with any doubt was checked against the surrounding minified code with `scripts/conductor-re/ctx.py`.
- Evidence for "Covered" is a scaffold file header, registry entry or backlog row for the behaviour. It does not mean the behaviour works: nearly all bodies are still placeholders.
- The strings show only what the UI says. Features that show no text in these three files, or only in `aria_label`, `label`, `placeholder`, `toast` and `description` files, are for the other passes.
- The "Run a shell code block" behaviour, the visualization frame and the "Continue" action were confirmed in the minified code. The merged state shows "Continue" except in the hover card. Which code-block languages get Run was not decoded. None of this was tested in the running app.
