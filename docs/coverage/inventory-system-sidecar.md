# Coverage check against Conductor: environment variables, error codes, log lines, constants and schema fields (sidecar bundle)

Scope: `env_var.tsv`, `error_code.tsv`, `log_message.tsv`, `numeric_constant.tsv`, `named_constant.tsv`, `schema_field.tsv` and `schema_literal.tsv` in `.context/conductor-re/inventory-system/`. Every row points at a line of `.context/conductor-re/sidecar.js` (written "@line" below). The bundle was read for behaviour only (D002); nothing here is copied code or prompt text.

Checked against `CLAUDE.md`, `docs/decisions.md` (D005 to D008, D013 to D016, D020 to D022), `docs/plans/backlog.md`, `docs/plans/items/`, `docs/plans/tauri-commands.md`, `docs/research/conductor/`, every file header and "Must handle" line in `packages/sidecar/src`, `packages/protocol/src`, `apps/desktop/src/core` and `apps/desktop/src-tauri/src`, and the earlier reports in `docs/coverage/`.

How to read it:

- Classes: **Covered** (a header, a "Must handle" line, a constant or a protocol field owns it), **Research only** (the research describes it, no scaffold file owns it), **Gap** (neither), **Deliberately different** (a decision or a header records the choice), **Out of scope** (team, hosted-service, Conductor analytics, the internal agent "Piccolo", the Muse Code agent behind an internal flag, the phone relay, Conductor's dev-only tools), **Planned** (a CLOUD or RC id).
- Two extra buckets keep the counts honest. **Library** is a row that comes from a bundled library (Sentry, OpenTelemetry, PostHog, zod, the MCP SDK, the Agent Client Protocol SDK, the Cursor SDK, the Anthropic SDK, QuickJS) or from a CI or cloud-region detector. **Noise** is a generic word such as `data` or `index`, a JSON Schema type name, or a debug trace line.
- "Kept" in the counts means rows that are neither Library nor Noise.

Notes on the counts:

- The 40 Gap rows and 76 Research only rows collapse into 31 behaviours (next section). The same behaviour often appears as an environment variable, a log line, a constant and a few fields.
- Out of scope is large because about half of the bundle is Conductor's hosted service. In `schema_field.tsv` one line (@5402) is the shared schema of Conductor's cloud API (workspaces, organizations, templates, automations, builds). 320 of its 350 names are Out of scope. Only the model catalog names on that line are kept (see "Model catalog").
- Out of scope also holds: the phone relay and pairing (@36914 to @43900: encrypted frames, `conductor.db` read-only access, device tokens), the cloud child process ("internal" mode, Roundhouse relay, message inbox, GitHub and cloud-identity token refresh, @338000 to @342000), the internal agent Piccolo (QuickJS code mode, tree memory), Muse Code and its own protocol "MSP" (@48404, @49220, @50400 to @50975, gated behind an internal flag per `docs/coverage/inventory-controls.md` row "Muse agent and models"), the dev-only "app-actions" HTTP server (@4262 to @4500, runs only for `APP_TYPE=dev` or staff), the exe-proxy tap (`EXE_PROXY_*`, @35176 to @35320; its default hook `PL` returns nothing, so it is off), the `conductor` cloud CLI (@346000 to @347526), and Sentry, PostHog and feature-flag lines.
- Planned rows map to: CLOUD-03 (idle sleep at 5 minutes, a maximum lifetime of 4 hours 55 minutes, keep-alive), CLOUD-04 (executable paths, Codex SQLite prewarm, out-of-memory attribution in the sandbox), CLOUD-05 (credential placeholders, per-spawn auth, GitHub token refresh), CLOUD-06 (sessions kept on disk across sandbox restarts), cloud sign-in calls for Codex and Cursor (`docs/plans/cloud-and-remote.md`, Part 1 item 6), and Spotlight sync for cloud workspaces (`checkpointTree`, `patchBase64`, `pushed*`).
- Deliberately different rows: no HTTP bootstrap and health endpoint (`sidecar.rs` header: D013 style supervision instead), send retries and the skipped-notification buffer (replaced by the write-ahead log, D007), the outbox open and write timeouts of 1 second (the sidecar refuses to run without a log, `sidecar-mode.ts` step 4), the model catalog fetch and its validation (the sidecar owns the model list, `models/catalog.ts` header), the 2 GiB logger memory (64 MiB, `log-ring.ts`), `listLocalhostPorts` (read with `lsof`, `ports.ts`), and the Claude auto permission mode (`permissions.ts` header).
- Covered rows include: the checkpoint script (60 s, 5 s, exit codes 101 and 102, 200 files), 50 events and 0.8 MiB per batch, the 100 recent message ids, the 10 s shutdown wait, the 10 s replay wait, the 30 minute idle stop, the 5 s and 3 s shell capture, the 20 s diff request, the 30 s tool bridge idle close, steering races, duplicate messages, and the ask-question count mismatch.
- Method for `schema_field` and `schema_literal`: each name was looked up as a whole word (and, for snake_case values, in camelCase) in the scaffold sources and plans, then in the research. Found in the scaffold means Covered, found only in the research means Research only, found nowhere means Gap. I then read every Gap and Research only name and overrode the ones where the scaffold uses a different word for the same thing (for example `branchRenamePending` is `placeholderBranch`, `generalPreferences` is `userPreferences`). Covered here therefore means "a counterpart exists", not "the counterpart behaves the same".
