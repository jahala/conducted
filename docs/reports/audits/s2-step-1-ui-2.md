# Audit s2-1-ui-2 (NAV-11, NAV-15, SET-07)

Read-only audit of branch `slice2/step-1`. Paths are relative to `apps/desktop/src` unless they start with `docs/`. Types, lint and test runs were skipped on purpose.

## NAV-11 Unread state and "next unread"

- MUST `features/sidebar/WorkspaceRow.tsx:109-116`: the hover key R is a `keydown` handler on the `<Link>`. Browsers send key events to the focused element, not the hovered one, so R does nothing for a row that is only hovered. The test (`WorkspaceRow.nav-11.test.tsx`) fires `keyDown` straight on the link after `mouseEnter`, so it hides this. The key is also hard-coded as `"r"` and ignores the `sidebar.toggleRead` binding in `core/registries/commands.ts:823`, so a rebind has no effect. Fix: register `sidebar.toggleRead` through the command dispatcher with a "hovered workspace" scope, and test it with a hover and no focus.
- MUST `features/sidebar/UnreadDot.tsx:1-9` and `features/workspace/TabItem.tsx:103-105`: two unread dots exist. `UnreadDot` says it is "used in rows and tabs" and is used only in `WorkspaceRow`. `TabItem` draws its own `<span role="img" aria-label="Unread" ... bg-unread>`. The two use different colours (`bg-accent` vs `bg-unread`). ui-map section 8 names an `unread` token, and `bg-accent` contradicts it. Fix: use `bg-unread` in `UnreadDot`, render `UnreadDot` in `TabItem`, delete the inline copy. The header's "Our design choice" about the accent colour has to go as well.
- MUST `features/sidebar/next-unread.ts:6-8`: the header says "Nothing unread (null, the button is disabled)". `NextUnreadButton.tsx:94-96` returns null, so the button is hidden, and its own header says "hidden". The two headers disagree. Fix: change next-unread.ts to "hidden".
- MUST `features/sidebar/next-unread.ts:50-60` against its header "chats that wait for the user first": the code knows only the workspace-level status. It picks the waiting chat by guessing (oldest unread, else the active chat, else the oldest open chat). A workspace with two chats, one waiting and one merely unread, can send the user to the wrong one. `markAllRead` knows the real answer (`openInteractions` / `liveStates[..].openInteraction`). Fix: pass per-chat "waits" into `UnreadCandidate` and pick the chat that waits. Add a test with two chats in one workspace.
- MUST `features/chat/ChatPane.tsx:36-42`: the effect that clears a workspace's unread chats on open (checklist: "Opening a workspace clears the unread dot of its chats, except chats that still wait") has no test. `ChatPane.test.tsx` mocks `NextUnreadButton` and only checks the regions. `sessions.nav-11.test.ts` tests `markAllRead` alone. Nothing fails if the effect is deleted. Fix: a ChatPane test over `createTestContainer` that mounts a chat and sees the sibling chat's count go to 0 and `viewingSessionId` set and then cleared on unmount.
- MUST `features/chat/NextUnreadButton.tsx:82-85`: the two handlers (`chat.nextNeedingAttention` Cmd+Alt+L and `nav.nextUnread`) are registered only while a chat is open. Both commands are `scope: "global"`. "Go to next unread" from the palette on Home, Settings or a terminal tab does nothing. No test covers either handler or the `useLiveShortcut` key hint. Fix: register the handlers at the app level (the sidebar or the shell), and add tests that dispatch each command id and check the navigation, plus a rebind test for the hint.
- MUST `features/chat/NextUnreadButton.tsx:44-67`: this rebuilds the workspace status for every workspace with `deriveWorkspaceStatus` and its own inputs. `useWorkspaceStatus` in `core/hooks` already does that per workspace. This is a second copy of the status rule (architecture.md puts it in `core/status/workspace-status.ts` for "every screen that shows a status"). It also passes `git: null`, so it can differ from the sidebar. Fix: take the status from one shared selector.
- MUST `core/services/sessions.ts:1115-1138` (`markAllRead`): after the awaited `clearUnread` calls it writes `unreadCount: 0` into the store from a snapshot. A new agent message that raised the count (via `EventIngest`) while the loop was awaiting is overwritten in the store but is 1 in the database. This is the newest-answer rule from engineering.md. Fix: re-read each session's count when setting the store, or run the writes through `createKeyedQueue` per workspace. Test with two overlapping calls.
- LATER `features/sidebar/WorkspaceRow.tsx:93-103`: pressing R on a row whose only unread chat waits for the user calls `markAllRead`, which skips it on purpose. The key press is a silent no-op and the row stays unread. Fix: say why in a toast, or flip to "unread" only when the state changes.
  Outcome: open, item NAV-11 (`toggleRead` still calls the workspace-wide mark and only toasts on an error, not on the no-op, `WorkspaceRow.tsx:161-172`).
- LATER `features/workspace/TabContextMenu.test.tsx:12-40`: the test replaces `useActions`/`useLiveShortcut` with `vi.fn` mocks instead of the real container (engineering.md: screens are tested over `createTestContainer`). `useLiveShortcut: () => null` means the live-hint rule is not tested. Fix: use the real container and assert a hint changes after a rebind.
  Outcome: open, item NAV-11 (`TabContextMenu.test.tsx:16-18` still mocks `core/hooks.ts` with `useLiveShortcut: () => null`).
- LATER `features/composer/SendButton.tsx:15,44-45`: hand-written `getCommand(...).defaultShortcuts[0]` is left. The NAV-11 checklist item "replace hand-written or default shortcut text with useLiveShortcut" was done for TabContextMenu and WorkspaceActionsMenu only. Fix: sweep this sibling.
  Outcome: open, item NAV-11 (`SendButton.tsx:48` still reads `getCommand("chat.submit")?.defaultShortcuts[0]`).
- LATER `core/services/sessions.ts:1380-1389` (`markWorkspaceUnread`): "newest chat" is `byWorkspace[id][0]` or a sort, and it can be a closed chat. Fix: pick the newest open chat, and test it.
  Outcome: open, item NAV-11 (`markWorkspaceUnread` still takes `byWorkspace[workspaceId]?.[0]` with no closed filter, `sessions.ts:1991-1993`).
- LATER `core/services/notifications.ts:173-183`: the failure path of `refreshDockBadge` (`setDockBadge` throws) has no test.
  Outcome: open, item NAV-11 (`notifications.nav-11.test.ts` still tests only the success path).

## NAV-15 Terminals and previews that survive tab switches

- MUST `app/SurfaceLayer.tsx` (whole file): `SurfaceLayer` and `SurfaceAnchor` have no caller outside their own test. Terminals and previews still unmount on a tab switch, so the rule "Terminals and browser previews stay alive when the user switches tabs" has no effect in the app. `TerminalView.tsx:9-12` still says it "must tolerate being unmounted". No item in `docs/plans/items/` tracks the wiring (only the NAV-17 row, which lists `SurfaceLayer.tsx` as a placeholder with no callers). engineering.md "Done means reachable" asks for a checklist item on the owner of the caller. Fix: add that item (tab strip and terminal/browser tabs render `SurfaceAnchor`; the shell owns the placements and renders the layer), then build it.
- MUST checklist items "The surface layout registry that places panels" and "The dialog manager that opens and closes dialogs" (services-map 1.5): no code and no test. The header moves the registry to "the caller", and nothing in `src` is called a dialog manager. Fix: build both, or move both items to the feature that will own them in `docs/plans/items/` and cut them from this issue.
- MUST `app/SurfaceLayer.tsx:1-18` header, "Must handle: a tab that closes (its surface is removed and disposed)": the layer only stops rendering the spec. Disposal of the PTY or webview is the caller's, and no code does it. Header line is not kept. Fix: cut "and disposed" or add the disposal path.
- LATER `app/SurfaceLayer.tsx:129`: the comment "keeping hidden ones mounted over their last known slot" is wrong. A hidden surface has no style at all and no slot. Fix: reword.
  Outcome: fixed already, 470e25c1 the comment now says a hidden surface "stays mounted but has no box on screen" (`SurfaceLayer.tsx:141`).
- LATER `app/SurfaceLayer.tsx:5-9` against `:154-182`: the design choice says the layer "measures nothing", and the same file measures in `SurfaceAnchor`. Say which part measures.
  Outcome: fixed already, 470e25c1 the header now says the layer "draws what it is given and measures nothing; the anchor is the part that measures" (`SurfaceLayer.tsx:9`).
- LATER `app/SurfaceLayer.tsx:177-178`: `report` runs on every `scroll` event in the document (capture phase) with no frame throttle, once per anchor. Fix: batch in `requestAnimationFrame`.
  Outcome: fixed already, 470e25c1 the scroll handler now schedules one `requestAnimationFrame` measure (`SurfaceLayer.tsx:190-201`).
- LATER `app/SurfaceLayer.tsx:123`: the layer is `fixed ... z-10`. No test shows it stays below menus and dialogs.
  Outcome: open, item NAV-15 (`SurfaceLayer.nav-15.test.tsx` has no assertion about layer order; the layer is still `fixed inset-0 z-10`, `SurfaceLayer.tsx:145`).

## SET-07 Repo pages: scripts, actions, prompts

- MUST `features/settings/repo/RepoMiscPage.tsx:211-214` and `FilesToCopyField.tsx:1-10`: the page always passes `matches={null}` and `source="settings"`. "Detecting files to copy...", the glob preview and the `.worktreeinclude` mode can never show in the app, so those checklist items have no live path. The component tests exercise props the page never sets. Fix: feed the field from a hook that lists matching files and detects `.worktreeinclude`.
- MUST `features/settings/repo/FilesToCopyField.tsx:7-8,82-86` against `core/services/workspace.ts:405-420`: the field says `.worktreeinclude` "takes over" and the list is read-only. `copyIncludedFiles` merges the settings patterns and the `.worktreeinclude` patterns (`[...fromSettings, ...fromFile]`). Header and UI text claim behaviour the code does not have. Fix: show both sources, keep only the settings list editable.
- MUST `features/settings/repo/RepoMiscPage.tsx:100-103,160-170`: `actions.projects.setIcon` is `notImplemented("PRJ-05")` (`core/services/repo.ts`, `setIcon`). "Save icon" and "Remove icon" call it through `void saveIcon(...)`, so a click gives an unhandled rejection and the user sees nothing. The test replaces `setIcon` with `vi.spyOn` and therefore never meets the placeholder. Fix: do not ship the Icon control until PRJ-05 exists, or leave it disabled with a visible reason; do not call a placeholder from a live screen.
- MUST `features/settings/repo/RepoMiscPage.tsx:157-160`: the icon input shows `icon === "" ? repoValue.icon : icon`. Deleting the last character sets `icon` to "" and the field snaps back to the saved icon, so the user can never clear it by typing. "Save icon" then re-saves the old icon. Fix: keep `null` for "untouched" and `""` for "cleared".
- MUST `features/settings/repo/RepoMiscPage.tsx:197-205` against the header "Branch new workspaces from": the control is a read-only input that shows `repoValue.defaultBranch`. The checklist rule says it needs a `RepoConfig` field and a control that creation uses instead of `repo.defaultBranch`. There is no field and no save, and the header claims "per-repository git overrides". Fix: add the field to `RepoConfig` and the settings file, or cut the claim and move the item back to WS-01.
- MUST `features/settings/repo/RepoMiscPage.tsx:79,89-91`: `remoteName ?? "origin"` invents a default for display and for the "no change" check. A repo whose real remote has another name shows "origin". Fix: show the real remote from git, or show an empty field with "origin" as a placeholder only.
- MUST `features/settings/repo/RepoMiscPage.tsx:271` against `RemoveRepoDialog.tsx:7-9`: the page passes `runningAgentCount={0}` always. The dialog's "Must handle: workspaces with running agents (listed, stopping them is part of confirming)" is never reached, and the dialog lists none (it only shows a count). Fix: count the running chats from the sessions service, and check that `projects.remove` stops them (the test at `RemoveRepoDialog.test.tsx:65` only covers the prop).
- MUST `features/settings/repo/RepoMiscPage.tsx:174` repeats `workspaceFolder` logic from `core/services/workspace.ts:330-332` (`<root>/workspaces/<repo>/<place>`). Two copies of the path rule. Fix: export one helper from the workspace service and call it.
- MUST `features/settings/repo/RepoScriptsPage.tsx:40-47`, `features/scripts-panel/run/AddActionDialog.tsx:40-47` and `core/services/terminals.ts:100-114` (`buildScriptEnv`): the list of `CONDUCTED_*` variables is written three times. Fix: derive one exported list from `buildScriptEnv`'s keys and use it in both screens, with a test that compares them.
- MUST `features/scripts-panel/run/AddActionDialog.tsx:2-3`: the header says it is "Used by the Run tab and by the repository Actions settings page". Only the settings page uses it. `RunTab` and `RunEmptyState` have no caller of it. Fix: wire the Run tab's "Add action", or cut the claim.
- MUST `features/settings/repo/*.tsx` (all four pages) have no caller: `SettingsScreen.tsx:20-23` is still `notImplemented("SET-02")`. `docs/plans/items` has no item that mounts the pages. Fix: add the wiring item on SET-02 per engineering.md "Done means reachable".
