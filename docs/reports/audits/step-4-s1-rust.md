## PLAT-09 Sidecar launcher

- MUST `apps/desktop/src-tauri/src/sidecar.rs:1038` (`shutdown`) is never called. `lib.rs` has no quit hook and `app_quit` does not use it. The header (line 36, "Quitting the app closes the socket, sends SIGTERM, waits briefly, then SIGKILL") is false, and the backlog row is `done`. On quit the sidecar only stops through its own parent watchdog. Fix: call `shutdown` from `app_quit` and from the `RunEvent::Exit` handler, and add a test that a running fake sidecar is gone after it.
- MUST `sidecar.rs:313-399` (`kill_orphans`, `orphan_pids`, `is_sidecar_process`) kills too much. It only spares the app's own pid and its direct children. A live sidecar of another running Conducted instance (dev next to release; no single-instance guard exists in code, only in header comments in `lib.rs`) is killed. With `CONDUCTED_SIDECAR_BIN` set, any process whose command line has a token with the same basename and a token `sidecar` is killed with SIGKILL, for example `bun run sidecar` when the wrapper is called `bun`. Fix: only kill rows with `ppid == 1` whose executable path equals a resolved sidecar path, and add tests for a live foreign parent and for an unrelated `bun ... sidecar` process.
- MUST `sidecar.rs:108-113`: duplicates signalling that already exists. It declares its own `extern "C" fn kill` and aliases `SIGKILL`, while `process_group.rs:19-33` already owns `killpg` and `signal_group`, which is meant to be the one home. `KILL_GRACE_MS` (`sidecar.rs:100`) also repeats `shell.rs:75`. Fix: the sidecar is its own group leader (`process_group(0)`), so use `process_group::signal_group(pid, SIGKILL)`, delete the extern, and import one grace constant.
- MUST Checklist item "A ready event tells the UI the sidecar connection is up" (frontend 3b) has no code. Nothing emits a ready event (`EVENT_LINE` and `EVENT_RESTART` only), and the header neither provides it nor says `sidecar_ensure_started` returning is the signal. Fix: emit `sidecar://ready` at the end of `start_locked`, or state in the header and the item text that the command result is the signal, then update the item.
- MUST `sidecar.rs:514-540`, header lines 48-49: the header says the variables "must match packages/sidecar". `config.ts` reads only `CONDUCTED_BIN_DIR`, `CONDUCTED_OUTBOX_ROOT` and `CONDUCTED_LOG_DIR`, and `sidecar-mode.ts` reads `CONDUCTED_PARENT_PID`. Nothing in `packages/sidecar/src` reads `CONDUCTED_APP_VERSION`, `CONDUCTED_AGENT_BINARIES_DIR`, `CONDUCTED_ACP_PROVIDERS_DIR` or `CONDUCTED_CURSOR_STORE_DIR`. The environment test (line ~1389) does not check the cursor store variable. Fix: remove the unread variables until their features need them, or add the readers; add a contract test that compares the two lists.
