## GIT-04 Git header state machine

- MUST (bug) `apps/desktop/src/core/services/git.ts:~407-411`: `stateOf` sets `uncommittedFiles` and `changedFiles` to the same `snapshot.files.length`. In `core/git/status.ts` a `full` poll compares against the merge base (all branch changes) and an `uncommitted` poll compares against HEAD. With a full snapshot, a clean tree with committed work reports uncommitted files, so the header says "Uncommitted changes / Commit and push" forever. With an uncommitted snapshot, `changedFiles` is only the working tree, so "Changes / Create PR" is unreachable after a commit. `git-header.test.ts` feeds the two numbers by hand, and `hooks/git.git-04.test.tsx:156-157` uses 2 and 2, so no test sees this. Fix: read the two counts from separate sources (porcelain status for uncommitted, the full compare for changed) and test a committed branch with a clean tree.
