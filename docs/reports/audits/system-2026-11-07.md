# System audit: data model, separation of concerns, complexity (2026-11-07)

The owner asked whether the data model, migrations, separation of concerns and complexity had ever been reviewed as a whole. They had not: the 36 earlier audits in this folder each read one pull request's diff. This audit read origin/main at 4f73c0b4. A Sonnet reader collected the evidence (`.context/day/audit/evidence.md`, not committed); the lead checked each finding below against the code before listing it. Findings are ranked by who is hurt and how likely it is.

## Fix now

1. **Recent activity never moves (bug the user sees).** `workspaces.last_activity_at` is set when a workspace is made, and `touchActivity` has no caller outside the catalogue seeds (`core/db/workspaces.ts:223`, `catalogue/seeds.ts:115`). The sidebar's "recent activity" sort (`features/sidebar/sidebar-view.ts:112`), Home, the kanban, the palette and back-navigation (`app/navigation-history.ts:108`) all read it, so they order by creation time. The seeds set the value, so every screenshot looks right. Issue #388.
2. **Removing a project leaves its secrets in the Keychain.** `RepoService.remove` (`core/services/repo.ts:884`) deletes the repository row, and `env_vars` rows cascade (`0001_init.sql:207`), but nothing deletes their Keychain entries. data-model.md promises the entry goes with the variable (SET-04). Issue #389.
3. **Three rules decide which names hold a secret, and they disagree.** Rust's log redaction (`src-tauri/src/logger.rs:659`) misses `GITHUB_PAT`, `SESSION_COOKIE` and `GH_AUTH`; the sidecar's (`sidecar/src/logging/logger.ts:348`) misses `AUTH`; the diagnostics report's (`features/diagnostics/diagnostics-report.ts:41`) misses `cookie` and `pat`. A value one runtime would hide is written in clear by another, and logs travel in Send feedback (APP-09). One rule, one table of names, and a contract test comparing the Rust answer with the TypeScript one. Issue #390.
4. **"Archived" has two homes that disagree while a workspace is restored.** `state = 'archived'` and `archived_at` are both set by `markArchived`, but unarchiving moves `state` to `initializing` and clears `archived_at` only when setup finishes (`core/db/workspaces.ts:204, 222`). Readers use one or the other (the sidebar and palette read `state`; Home, the kanban, terminals and `workspace-open.ts` read `archived_at`), so during a restore the workspace is archived on some screens and not on others. One predicate in core, used everywhere. Issue #391.

## Fix soon

5. **The largest table has no index for its startup and daily scans.** Startup repair's `findInterruptedTurns` (`core/db/session-events.ts:119`) and the lifetime job's `cutToolOutputs` and `findCompactableTurns` (`core/db/lifetime.ts:87-139`) filter `session_events` by `type` and `received_at` and read `content` with `json_extract`, with no index on either column. Conductor's database grew to 12 GB (D006). Measure the queries on a database of real size before and after adding indexes; add only what the measurement shows. Issue #392.
6. **Repository methods and columns that nothing uses.** No production caller: `workspaces.touchActivity` (item 1), `setNotes`, `clearPullRequest`, `getByPath`; `repos.reorder`, `setName`, `setDefaultBranch`; `diffComments.setOutdated`, `countOpen`, `supersedeWorkspace`, `listByFile`, `listByThread`; `terminals.setSize`, `listActive`; `sessions.clearWorkspaceUnread`, `unreadByWorkspace`; `backlogWorkspaces.update`, `setSection`. `session_events.compacted_at` is written and never read; the JSON carries its own `compacted` flag. Each is either a feature of Conductor's we never wired (then wire it, with its row), or dead (then remove it with its column in a new migration). Issue #393.
7. **Docs that the code contradicts.** architecture.md says there is no module-level mutable state (there are zustand singletons in `ui/Toast.tsx`, `app/overlay-store.ts`, `app/command-dispatcher.ts`, and `OnceLock`s in `terminal_history.rs` and `binaries.rs`) and that the sidecar's I/O edges live in `adapters/` (raw `node:fs`, `Bun.spawn` and `process.env` appear in at least ten other sidecar modules). data-model.md says the event limits are settings (lifetime.ts says no setting changes them), that `settings` is a fixed set of keys (the lifetime job stores its own key), and lists one localStorage key of five. Fix each doc or the code, and give each true rule a guard. Issue #394.

## Track

8. **One fact, several homes, kept in step by hand.** Linked folders (`workspaces.linked_paths` and each chat's `additionalDirectories`, patched only for chats in memory, `core/services/sessions.ts:1307`); the context window (two session columns, `model_context_windows`, usage events and a store); attachments (a table, two path lists and the event). Each copy needs a reason or goes. Issue #395.
9. **Boundaries that are stated but not enforced.** Features import 102 times from core internals other than `hooks`, `api`, `model` and `context`, 85 times from other features, and 36 files import `app/command-dispatcher.ts`. The Biome rule bans only `core/db` and Tauri. Decide the real rule, then make Biome hold it. Issue #396.
10. **Services that own many features.** `GithubService` (3,891 lines, 12 feature ids, 42 public methods), `SessionsService` (2,532 lines, 65 public methods), `WorkspaceService`, `GitService`, `binaries.rs`, and `createContainer` (one function of 1,134 lines). Split along the feature ids when each is next changed, with no behaviour change in the split. Issue #397.

## Guards this audit adds or asks for

- A fact with two homes is the pattern behind items 1, 4 and 8. The data-model guard cannot see it, since it reads the schema, not the code. The rule goes in docs/architecture.md ("one home per fact; a copy names its reason and the code that keeps it in step"), and the per-PR audit prompt asks for it by name.
- Item 3 gets its contract test; item 7's rules each get a guard or are marked "not held yet".
- Item 6's dead methods would have been caught by a guard that fails on an exported repository method with no production caller. `test-only-exports` already does this for modules; extending it to repository methods is part of #393.
