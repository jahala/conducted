## RUN-01 Run actions with start and stop, concurrent or exclusive

- MUST `core/services/run-scripts.ts:225-236,579` (stuck "Starting..."): `stop()` called while a start is in `starting` finds no process in `#processes`, so it returns `run_not_running` (an error toast) instead of cancelling. Its `nextAttempt` has already invalidated the start, and `#launch` (line ~555) then stops the new terminal and returns without setting a phase. The phase stays `starting` and the button stays disabled forever. The same happens to another workspace's start in exclusive mode (`#stopOtherWorkspaces` bumps that workspace's attempt, line ~596) and to `stopWorkspace`. Fix: when `#launch` bails out as stale, set the phase to `stopped` through the newest attempt, and let `stop()` during `starting` succeed. Add the failing test first (stop during a slow `runScript`).
- MUST `core/services/run-scripts.ts:202`: `start` awaits `#stopProcess` and drops its Result. A previous action whose stop is not confirmed is ignored, the new action starts beside it, and `#clearOutcome` on the next line erases the "stop-unconfirmed" outcome just recorded. Header says "a stop that is not confirmed is returned to the caller". Fix: return the error from `start` (or start and keep the outcome visible). Test it.
- MUST header vs checklist, `run-scripts.ts:19`: header says "Run history lives in memory"; the issue says "keeps the last 20 task ids per workspace across restarts" and "run script history is kept up to a size limit". The code keeps history only in the zustand store. Hidden actions are "remembered" the same way (checklist). Either build the stored history or move those items to a feature with a reason.
- MUST `core/services/run-scripts.ts:426` and `core/services/workspace.ts:1128-1156`: the issue lists "Archive side effect: stop the workspace's runs and clear its run history". Archive never calls `stopWorkspace` (only `cancelSetup` when setup runs) and never calls `clearRuns`, so a dev server keeps running inside a worktree that is then removed. `clearRuns` also leaves `history`, `#lastRunIds` and `#attempts` behind. Fix: call `scripts.stopWorkspace` then a clearing method that also drops history, from `#archiveNow` before the snapshot; add it to the `scripts` dependency type and test it.
- MUST (dead code) `core/services/run-scripts.ts:394,399,409,421,426`: `onSetupFinished`, `stopAllForRepository`, `isBusy`, `lastRunId` and `clearRuns` have no caller outside tests. The checklist item "Busy check, last run id, clearing runs, kill for a repository ... are supported" is met only on paper. Wire them (workspace removal, repo removal, busy checks) or add wiring items to the owners.
- MUST `core/services/run-scripts.ts` `outcomes`: the store keeps `"stop-unconfirmed"` but no component reads it (`grep outcomes` finds only the service and its test). Header and checklist ("retained outcome") claim a user-visible result. The toast from the stop call is the only signal. Read it in `RunTab` or drop the field.
- MUST (Spotlight rule): checklist "Spotlight is always exclusive" and header "run mode exclusive also stops other workspaces' actions" cover only run actions. Nothing stops a Spotlight terminal or is stopped by one. RunState always reports `spotlight: { active: false }` (`run-scripts.ts:149`). Mark it as RUN-04's, or build it.
- MUST (plausible, from code only) `core/services/terminals.ts:399,466-470`: `record.history` is created empty and never filled, and `onData` hands the chunks held in `pending` to the first listener. `runScript` adds the URL listener first, so it takes them. ## RUN-07 Terminal output for the GetTerminalOutput tool
