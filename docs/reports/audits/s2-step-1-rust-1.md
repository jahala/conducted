## PLAT-06 File search

- MUST `file_search.rs:100-112`. `walk_builder` uses `standard_filters(true)`, which also turns on the walker's hidden-file filter. Dot-files and dot-folders (`.github/`, `.gitignore`, `.env.example`, `.context/`) never appear in the tree, Quick open or `@` search. The header (lines 26-28) says the built-in set exists "even when a custom filter would allow hidden folders", which implies hidden entries are allowed. The research (native-and-sidecar-map.md, line 79) lists `.github`, `.context` and `.conductor` as paths Conductor handles explicitly (D020). Fix: call `.hidden(false)` and rely on `always_ignored()` plus the ignore files, then add a test that lists `.github/workflows/ci.yml`. Or, if hidden entries are meant to stay out, change the header and the issue.
- MUST `file_search.rs:380-383`. One unreadable or vanished file aborts the whole grep with `search_read_failed`. Agents edit worktrees constantly, so a file deleted between the walk and the read is a normal event. The same goes for `walk_error` at lines 114-119, 156 and 179: one permission-denied folder makes `search_list_tree` and `search_fuzzy` fail completely. Fix: skip entries that disappeared (`NotFound`), and either return partial results with a count of skipped paths or document that failure is intended. No silent skip.
- MUST `file_search.rs:246-264` and test at 601-615. The header (lines 23-24) claims ranking is "by score, then shorter path, then alphabetical". The only ranking test asserts `results[0]` is `alpha.ts` and the length. The tie-breaks are not tested and would still pass if removed. Fix: add a test with equal-score paths (for example `a/x.ts` and `b/x.ts`, and a longer path) that asserts the exact order, and run it twice.
- LATER `file_search.rs:176-191`. `collect_files` keeps only regular files. Symlinks to files are dropped from fuzzy results, while `collect_tree` lists them. The header does not say so. Decide which is right and test it.
Outcome: open, item PLAT-06 — `collect_files` still keeps only `is_file()` entries while `collect_tree` lists symlinks (`apps/desktop/src-tauri/src/file_search.rs:387-405`), and no test covers a symlink to a file.
- LATER `file_search.rs:500-525`. The header says the walk honours `.git/info/exclude` and the global ignore file. Only `.gitignore` is tested. Add tests for the other two. The global ignore file needs the test to set `XDG_CONFIG_HOME` or `core.excludesFile`.
Outcome: open, item PLAT-06 — the header still promises `.git/info/exclude` and the global ignore file (`file_search.rs:16`), but only `.gitignore` and a built-in `.git` exclusion are exercised in the tests.

## PLAT-11 Notifications and Dock badge

- MUST `notifications.rs:23-24`. Header: "the system notification sound is used". `notify` never calls `.sound(..)` (lines 115-123), and `notify-rust` sets a sound on macOS only through `sound_name` (`macos/nsusernotifications.rs:210`, `unusernotifications.rs:231`). The notification is silent. The issue says sounds fire for agent events and offers default or none. Fix: call `.sound("default")` when the sound setting is "default", and take a `sound: bool` (or name) in `NotifyRequest`. Add a test of the builder choice. Otherwise remove the claim.
- MUST `notifications.rs:147-151`, header lines 12-17. Cold-start clicks cannot work. The click handler is installed lazily on the first `notify` call (`install_click_handler`), and the plugin reports only notifications shown after a handler exists, by the same process (the plugin docs say so, and `show_tracked` waits on a thread in the process that created the notification). A click that launches the app produces no `on_action` call, so `notification_take_pending` can only hold clicks from the running process. The issue item "queued during a cold start" and the checklist command name are therefore not delivered, and the header implies they are. Fix: either register the handler in `setup` and handle the launch click through the `deep-link` plugin (`conducted://` URL, PLAT-16), or reduce the claim to "a click before the UI attached its listener". Add a test that goes through `install_click_handler`.
- MUST `platform/tauri.ts:889-907`, `notifications.rs:68-71`. Issue item: "a cold start uses only the newest link". `take_pending` returns every queued link and `drain` calls the listener for each one, so a cold start opens every queued chat in turn. Fix: keep only the last link (in `take_pending` or in `drain`), and test it with two queued clicks. The current test `plat_11_clicks_are_returned_oldest_first` asserts the opposite.
- LATER `platform/tauri.ts:889-897`. `drain` calls `takePending` before it checks `active()`. A click that arrives after `onClicked` was unsubscribed is taken and thrown away, so a later subscriber never sees it. Check `active()` first, or put the links back.
Outcome: fixed already, 47a5ddd3 — `drain` now checks `active()` before `takePending` and again after (`apps/desktop/src/platform/tauri.ts:1011-1021`).
- LATER `notifications.rs:125-143`, `173-193`. `notify`, `set_dock_badge` and the handler glue have no test. Only `record_click`, `take_pending`, `accept_link` and `badge_label` do. The header lines on `notification_denied` (the plugin always returns Granted, so the branch cannot be reached on macOS) and the "handler registered before the first notification" claim need a test or a note.
Outcome: open, item PLAT-11 — the tests still cover only the helpers; `notify`, `set_dock_badge` and the click-handler glue have no test (`apps/desktop/src-tauri/src/notifications.rs:242-333`).
- LATER Checklist items "Notifications service decides when to notify", "Dock badge counts workspaces with unread chats, excluding archived", "controlled by the notification and completion-sound settings". Rust has no logic for them and `grep` finds no UI caller of `notify`, `setDockBadge` or `onClicked`. CHAT-19 (backlog row 184) owns the caller.
