# Audit: batch n7-s1-ui (branch overnight/step-7 against main)

Read-only audit. Files are under `apps/desktop/src/features/workspace/` unless a path says otherwise. Not run: the test suite, the app. Everything below comes from reading the code and tests.

## NAV-10 Center tab strip

### MUST

1. **TabStrip.tsx:199-203, 205-222. Closing any tab, not only the active one, switches the view to a neighbour.** `close` always calls `showNeighbour(tab)`. Closing an inactive tab (middle click, X button, or the context menu "Close") jumps away from the tab the user is on. The header says "closing the active tab opens its neighbour". Fix: only call `showNeighbour` when `tab.ref === activeRef`. Add a test that closes an inactive tab and asserts `onSearchChange` is not called. The only close test closes the active tab.
2. **tab-layout.ts header line 9-12 ("reopening the last closed tab restores its group").** No function in tab-layout.ts reopens or remembers a closed tab. The test `reopens a closed tab in its group` (tab-layout.nav-10.test.ts:109) only calls `open` on an empty layout, so it would pass without the claim. Reopen is done in TabStrip.tsx:231-249 from a component `useRef`, which holds one tab and is lost on remount. Fix: either add a `closed` stack and a `reopen` action to the model and test that the tab returns to its group, or cut the claim and rename the test.
3. **tab-layout.ts header ("moving a tab to its own group is a no-op"), code at tab-layout.ts:263-268.** Moving a tab within its own group reorders it and makes it active; it does not return the same tree. No test. Fix: make it match the header, or change the header to say "reorders".
4. **tab-layout.ts header ("The service layer saves the tree per workspace"). No service saves it.** `TabGroupNode` is used only by SplitPanes, which keeps it in `useState` (SplitPanes.tsx:87). Nothing persists it. The `TabAction` cases `open`, `move` and `activate` have no live caller; only `split` and `close` are reached. The "store: top tab bar state" checklist item and "Persist closed tabs and a recent-workspace list" are not built. Fix: cut the claims, move the unbuilt items to a new item, and delete or wire the unused actions.
5. **SplitPanes.tsx:120-126, 141-148. A drop on a group never uses an edge.** `drop` splits to the right wherever the tab lands, including on the strip and on the second pane. The header ("Test first: dropping on the right edge"; "Drag tabs between groups or to an edge") promises edges, left, top and bottom splits, and moving a tab between groups. `applyTabAction` supports `edge` and `move`, but the UI never calls `move`, and `split` is only ever called with `edge: "right"`. No drag ghost is built (`setDragImage` does not appear anywhere). The test fires one drop on `split-centre` and would pass with no edge logic. Fix: compute the edge from the pointer position, call `move` for a drop on another group's strip, set a drag image, and test left/right/top/bottom.
6. **SplitPanes.tsx header ("the same tab is never in two groups" in tab-layout, "copied there rather than removed" here).** The tab shows in both panes, the layout copy is thrown away (`splitTab` reads only the first tab of the second group), and the second pane keeps a stale snapshot. If the chat is closed in the main strip, the second pane still renders it. `layout` is also never reset when `workspaceId` changes, so a split from one workspace carries into the next, unless the parent remounts; WorkspaceScreen does not key SplitPanes. Fix: derive the split pane from live tabs, reset on workspace change, and test both.
7. **SplitPanes.tsx:104-112. Cmd+D on a workspace with one tab does nothing, silently.** `split` refuses (the group has under two tabs) and the handler still returns `true`. Fix: return `false` or toast.
8. **SplitPanes.tsx:36-61 (`activeFromDescriptor`) drops a file tab's `mode`, `scope` and `line`.** The second pane always opens a file in diff mode on the branch scope, whatever the URL says. Fix: carry the real values, or put them on `TabDescriptor`.
9. **Duplicated logic: the tab ref string is built and parsed in four places.** `activeRef` as a nested ternary (TabStrip.tsx:183-196), `refOf` (SplitPanes.tsx:63-80), `activeTabKey` (active-tab.ts:62-77, same strings), plus `patchFor` (TabStrip.tsx:124-139) and `activeFromDescriptor` (SplitPanes.tsx:36-61) as inverses that parse with `slice("file:".length)`. Fix: one `tabRef(ActiveTab)` and one `activeTabFromDescriptor` in active-tab.ts or tab-layout.ts, used everywhere.
10. **Duplicated logic: new chat, new terminal and open browser are written three times.** TabStrip.tsx:256-272 (`chat.newTab`), NewTabMenu.tsx:41-85 and EmptyTabGroup.tsx:32-66. The browser URL (`http://localhost:${port}` else `http://localhost`) is the same code in NewTabMenu.tsx:80-85 and EmptyTabGroup.tsx:62-66. The "else `http://localhost`" is an invented default when the port is 0. The three also behave differently: EmptyTabGroup ignores the big-terminal preset that NewTabMenu honours (EmptyTabGroup.tsx:51 vs NewTabMenu.tsx:64-68). Fix: one `useNewTab` hook returning `newChat`, `newTerminal`, `openBrowser`. When the port is unknown, disable Browser or show an error instead of inventing a URL.
11. **Shared helper copied: hand-rolled single-flight guards.** `creating` ref (TabStrip.tsx:254-270), `busy` state (NewTabMenu.tsx:37-45, 60-62), `busy` state (EmptyTabGroup.tsx:30-34), `retrying` state (TabStrip.tsx:159, 291-293). docs/architecture.md says use `createSingleFlight`. The NewTabMenu and the Cmd+T handler also do not share one guard, so Cmd+T during a menu click makes two chats.
12. **Duplicated logic: the chat tab status is worked out inline** (TabStrip.tsx:171-180: `openInteraction` gives `needs_answer`, `working` gives `working`). docs/architecture.md says workspace status (sidebar, Home, tabs, Git panel) has one home, `core/status/workspace-status.ts`. Fix: call that function, or add the chat-level mapping there.
13. **Checklist: "Comment tab 'Comment by <author>'" is not built.** TabStrip.tsx:68 titles every comment tab "Comment". The TabItem header ("comment tab 'Comment by <author>'") claims it. The CommentTab body is REV-03's placeholder, which is fine; the tab title is NAV-10's. Fix: pass the author in, and test it.
14. **WorkspaceScreen.tsx:47 passes `tabStrip={null}`; the tab strip lives inside SplitPanes inside WorkspaceGate.** WorkspaceLayout's `tabStrip` slot (WorkspaceLayout.tsx:34, 75) is dead code. WorkspaceGate's header says "The header, tab strip and right panel stay in place so the window does not jump", but the strip is a child of the gate, so it disappears for the archived notice, the loading state and the error state. The WorkspaceLayout header ("header, tab strip and content in the centre ... All four are slots") and the WorkspaceScreen header ("assembling ... tab strip") are also off. The WorkspaceScreen test asserts regions but not where the strip sits. Fix: render `TabStrip` in the `tabStrip` slot (SplitPanes then only handles the content split), or drop the slot and fix the three headers.
15. **WorkspaceActionsMenu.tsx:238-252 (`surface="context"`) has no live caller.** The only user is WorkspaceHeader with `surface="dropdown"`. Checklist "Right-click on a row opens the Workspace actions menu" is not done: `features/sidebar/WorkspaceRow.tsx` does not use it (its header says the actions menu "is NAV-10"). No test covers the context surface. The header says "the sidebar row can show the same items", which is true of the code and untrue of the app. Fix: wire it into WorkspaceRow, or cut the checklist item and the claim and file the wiring as an item (docs/engineering.md "Done means reachable").
16. **RenameDialog.tsx header ("rename a workspace or a chat") is not kept.** "Rename chat" does not use it: TabContextMenu.tsx:129-150 has its own Dialog and form. Two dialogs for one job. The 'Rename chat' dialog on the checklist is therefore not this component. Fix: use `RenameDialog` in TabContextMenu and delete the second dialog.
17. **RenameDialog.tsx:20, 46-52. Failure travels as a throw.** `onSubmit` returns `Promise<void>`, and the three callers turn a `Result` into `throw new Error(...)` (WorkspaceHeader.tsx:202-205, 212-215; WorkspaceActionsMenu.tsx:258-261, 268-271) so the dialog can catch it. docs/engineering.md says failure lives in the return type. The catch also invents a message ("The name could not be saved."). Fix: `onSubmit: (name) => Promise<Result<unknown>>` and show `result.error.message`.
18. **Duplicated logic: the Rename workspace dialog is built twice** (WorkspaceHeader.tsx:197-206 and WorkspaceActionsMenu.tsx:253-262, same `workspaces.rename` call; initial name differs: `data?.displayName ?? name` vs `data?.displayName ?? ""`). The header's Target branch dialog (WorkspaceHeader.tsx:217-255) is a third copy of the same form. The unarchive call with `{ branchName: null, clearChats: false }` is also written twice (WorkspaceGate.tsx:34-37, WorkspaceActionsMenu.tsx:181-184). Fix: the header's button should open the actions menu's rename (or share one hook), and one `unarchive` helper should serve both.
19. **WorkspaceGate.tsx header ("Workspace not found", "It may have been deleted...") is not kept.** The gate shows the workspace error's own message under "Error loading workspace". The sentence "It may have been deleted" appears nowhere in the source. The test (WorkspaceGate.nav-10.test.tsx:43-50) only matches the message the test itself supplied, so it proves nothing about "Workspace not found". Fix: map the not-found error code to the "Workspace not found" card with the deleted hint, and test with the real not-found error; or cut the claim.
20. **Missing checklist items marked done.** No code and no test for: drag ghost (see 5); "PR and git buttons move into the header when the right panel is closed" (the header has none, WorkspaceHeader.tsx:184-195); "Drag a terminal from the right panel into the centre"; "The UI that opens terminals.openForRepo"; "The terminal-side action that calls composer.addText"; "Report the composer failure in the terminal UI"; "Composer minimises when a content tab is open" (Composer.tsx:18 says it is moved; no sender); "Persist closed tabs and a recent-workspace list"; "Terminal group: initialise the workspace's saved terminal tabs" (only `loadWorkspace` in TabStrip's retry; the hook loads lazily); "Branch name in the header: Copy (C) and Rename (R)" (no C or R keys, WorkspaceHeader.tsx:110-118). The backlog row for NAV-10 was set to `done` (docs/plans/backlog.md) with these open. Fix: build them, or move them to rows that own them and set NAV-10 per what exists.
21. **Checklist items with no test that would fail without the feature.** TabStrip: Cmd+W, Cmd+Shift+T reopen, previous/next tab, Cmd+T (`chat.newTab`), Cmd+D (SplitPanes), terminal close, close-failure toast, Tab Freak Mode limit of 10 (only the limit of 5 is tested, via a mocked menu: the "at the limit" test finds the text "at the tab limit", which comes from a stand-in, not from NewTabMenu), Retry calling the services, the tab status icon, the "Loading tabs" state. WorkspaceActionsMenu: Mark as read/unread, Set status (only the label is checked, no click), Move to section, New section, Rename, Copy link, Archive, Unarchive click, context surface. WorkspaceHeader: Rename workspace, Rename branch, Copy branch, Target branch, the Workspace actions button, loading and error states, archived (no Open in). WorkspaceGate: Unarchive click. SplitPanes: Cmd+D and close pane. TabContent: "This chat tab failed to render" card, split override. RenameDialog: Enter, Escape, selected-on-open. Error cards: "Tabs failed to load" Retry click.
